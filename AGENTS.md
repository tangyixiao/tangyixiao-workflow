# Project work

Use Node >=22 and its standard library. Reuse the current checkout and runtime;
do not add a dependency, daemon, client credential or telemetry for an ordinary
check. Run `npm test` and `npm run check` after substantive code changes.

The source repository is the maintained rule and tool source. Keep the installed
Skill self-contained and the CLI usable offline. Do not claim an instructions
file or a check grants permissions, enforces OS quotas, proves publication or
establishes visual quality. Report source, local checks, CI, installation,
client discovery, publication and actual use separately.

All project and installation mutations are plan-first with explicit apply.
Preserve project-owned configuration, dirty files and human edits. Guard managed
content with hashes, validate receipt paths before using them, and refuse links
that escape an intended boundary. Uninstall removes only unchanged managed files.
Resource commands in this alpha report ownership and cleanup candidates; they do
not kill processes or recursively delete scratch. The agent remains responsible
for authorized, verified task cleanup.

Use one task-owned work namespace, a 10 GiB reserve, a 1 GiB temporary-growth
review point and a 2 GiB optional expansion budget for ordinary work. Default to
one heavy job and diagnostic logs below 20 MiB. Do not clean unrelated caches,
worktrees, credentials or release assets. Preserve unique commits and dirty work;
respect rejected deletion operations.

New websites and substantial redesigns require real references, a desktop/mobile
visual overview and explicit human selection before implementation. Routine fixes
inside an approved direction continue without another approval cycle. This alpha
adds no new website or visual redesign. Public prose describes product facts and
verified behavior, with no private chat narratives or invented progress.
