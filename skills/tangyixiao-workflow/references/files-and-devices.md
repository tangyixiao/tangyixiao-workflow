# 文件去向与跨设备环境

## 提交前的三个判断

先看目标仓库、目标分支、可见性和暂存区的实际内容。用 `git diff --cached --stat` 查看范围，再查看有关文件的实际差异和新增二进制资产。删除文件的提交可能仍有历史副本，.gitignore 只影响未跟踪文件。检查 Markdown 附件、压缩包的成员、截图、日志、构建产物和 Pages 内容中是否夹带私有信息。

1. **平台收不收得下？** 查接收服务的单文件限制、传输方式、LFS 支持、配额和协作者拉取成本。GitHub 普通 Git 对超过 100 MiB 的文件有限制，网页上传另有更低限制，其他托管服务按各自规则。能压缩或拆分并不能解决权属或公开范围问题。[GitHub 文件限制](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)
2. **这个文件值得进版本历史吗？** 源码、可重建环境的配置、必要的小样例通常适合。可重新生成的缓存、依赖目录和临时录制留在本地；持续维护的大型源素材可在许可与配额合适时用 LFS。面向下载的安装包、成片或大数据集优先使用项目选定的 Release、包注册表或资产存储，仓库记录版本、来源与校验信息。
3. **谁可以看到？** 核对作者和上游许可、再分发权、个人信息、肖像、内部资料及公开授权。分别考虑 Git 历史、PR/Issue 附件、Actions 日志和产物、Release 与 Pages 的受众。私有仓库也可能对协作者、自动化账号或服务可见。密钥、令牌、cookie、真实账号库和签名私钥使用凭据管理器。配置示例使用占位值。权属或受众不清时先交付脱敏草稿，隔离有问题的文件再确认。发现已暴露的凭据，先撤销或轮换，再按宿主流程处理历史和通知。[GitHub 敏感数据处置](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)

## 换设备后如何接着做

优先使用项目已有的运行时版本文件、包管理器锁文件、构建预设、CI 矩阵和安装说明。记录影响结果的 OS、架构、工具链版本；GPU 工作再记后端和驱动要求。把公共默认值和个人覆盖分开。路径用相对路径或环境变量，命令区分 PowerShell 和 POSIX shell；留意大小写、换行、执行位、临时目录及权限差异。

| 随项目同步 | 在每台设备单独准备 |
| --- | --- |
| 同一提交、依赖版本、项目配置、脱敏示例、已有引导脚本、最短可运行用例 | 凭据、签名材料、绝对路径、SDK/驱动安装、缓存及本机配置 |

交接时先指出源设备上的提交、分支、尚未提交的独有修改和下一条验证命令。目标设备先检查目录冲突、已有运行时与磁盘容量，取同一提交，按锁文件恢复依赖，用该设备自己的凭据执行最短用例。二进制或 Git 未跟踪的必要工作通过获准渠道传输并核对哈希。保留源设备上的独有内容直到接收端核验完成。CI 仅代表其运行器；另一台设备尚未实际运行时，如实注明待验证。
