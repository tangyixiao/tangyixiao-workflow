# 弄清需求、安排计划、判断何时请人决定

## 从一次实际使用问起

先读已有的任务说明、样例、相关讨论和已经作出的决定，再沿使用者的操作走一遍。找出谁在做什么、卡在哪一步、现在怎样绕过去，以及做到什么程度才算解决。对方点名的实现要保留，弄清它是必须遵守的约束，还是对方想到的一种办法。

假设报销工具收到“加个 Excel 导出”的请求。财务每月把审批通过的报销单逐行抄进记账系统，附件里已有该系统的 CSV 导入样例。到这里可以确定重复录入的环节和记账系统接受的一种格式。若现有材料还没说明审计要求，就问“月底交付时，除了导入记账系统，还必须交一份 Excel 工作簿吗？”答案会改变交付物。

如果财务只需要入账，就约定用一份脱敏月结样本验收。把导出的审批记录导入记账系统，逐笔核对日期、金额和单号，再核对该月合计。如果审计还要求工作簿，把这项要求和审计模板一并纳入范围。将样例已经证明的事实、仍待核实的推测和明确要求分别写清。已有材料足以定下验收办法时就开始做。

## 计划写到能安排下一步为止

小修复用已有 issue 里的一两句话即可。跨阶段的工作可以在同一份项目计划里写近期、中期和远期，也可以分别链接项目已有的任务单、里程碑和路线图。按能验证的结果和实际依赖划分阶段，只有确有期限或已作承诺时才写日期。

| 什么时候用 | 需要写清楚什么 | 同一报销工具的计划示例（假设只需入账） |
| --- | --- | --- |
| 短期，下一项工作已可动手 | 本次交付、所需样本、验收方法和结果记录位置 | 给已审批列表加上按月导出入口。样本含本月两笔已审批、一笔待审批和上月一笔已审批。选本月应只导出本月两笔已审批记录。财务用记账系统试导，核对单号和金额，在任务单记下结果。 |
| 中期，几个交付之间有先后关系 | 每个里程碑要产生的可用结果、前置条件，以及怎样知道可以进入下一步 | 先凭试导结果确定必填列和格式。等财务提供跨月退款的脱敏样本，再验证退款金额和月份归属。两项通过后，由财务在一次月结中使用导出文件，记录仍需手工处理的条目。 |
| 长期，需要决定今后往哪里投入 | 希望改善的业务结果、当前范围以外的事项，以及什么新证据会改变方向 | 目标是让财务以审批记录完成月结，只人工处理异常。当前只覆盖现用的记账系统。出现第二套系统，或月结记录显示重复录入仍占主要工时，再决定是否支持另一种格式或直接对接。 |

若短期样本导入失败，就在原计划记下失败原因，并调整依赖它的里程碑。远期设想可以继续保留为备选，等触发条件出现再拆任务。

## 让使用 AI 的人知道事情进到哪一步

先写对方现在能做什么，再写已经验证到哪一步。需要对方选择时，说清选择会影响什么。日志、命令或实现细节放在对应证据旁边。以下仍以报销工具为例。

- 笼统的说法是“导出链路已打通，端到端能力待业务侧闭环”。
- 可以直接写“现在可以按月导出已审批报销单。本地样本导出了两笔，单号和金额都对得上。试导需要财务账号，请财务同事把这份样本导入记账系统，核对是否也出现这两笔记录。”

## 继续做、请人决定，还是停下来

| 判断 | 行动 |
| --- | --- |
| 目标和范围已明确，下一步在已有授权内，结果可检查，做错也容易撤回 | 自行继续实现、测试和修复。已有授权对同一目标和范围继续有效。样本缺少一种普通边界情况，可以补上并说明依据。 |
| 两种答案会改变交付物、兼容性、成本或使用者日后的工作，且现有材料无法决定 | 写出具体取舍，问一个能区分两条路的问题。在收到答案前，先做两种选择都用得上的工作，例如核对字段和准备样本。 |
| 缺少动作所需的授权或由指定人员作出的选择 | 停在该动作之前。新网站或大幅改版应先展示参考站点研究和桌面、移动端设计概览，等对方明确选定再实现。覆盖共享数据、合并或对外发布前，核对授权是否覆盖具体对象和动作。 |
| 授权已被撤回、操作遭到明确拒绝，或必需的账号、样本、环境确实无法取得 | 停下受影响的工作，保留已有结果，写清卡在哪一步、需要什么才能继续。仍能独立完成的核查可以继续。 |
